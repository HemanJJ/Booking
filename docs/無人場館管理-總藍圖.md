## 四、LINE 主線（脊椎）

- **身分主鍵 = LINE userId**：booking 會員✅；smartlocker 靠「傳取件碼綁定」把遊客變會員；行銷 lead 之後也要對到同一把鑰匙。
- **平台原則（本會話金句）**：登入是我的（平台），粉絲是他的（業者）。
- **分眾**：訂位通知、穿線取件、販售收據、行銷訊息——同一 OA `@014uppgb` 一條龍發，行銷順著既有觸點進去，不必另買廣告。
- ⚠️ **帳號整併待辦**：歷史線索有 `@647ntnvu`（迪飛羽球館）與 `@014uppgb`（羽拍有約），藍圖以 `@014uppgb` 為主，舊帳號別再投入資源。

## 五、無人化五個閉環（每個閉環 = 一條自動化鏈）

| 閉環 | 流程 | 自動化的卡點 |
|------|------|-------------|
| 1. 訂位 | 訂位 → 付款 → 確認 → 取消/釋放 → no-show 停權 | **LINE Pay 憑證**（付款）；no-show 自動化（任務 3） |
| 2. 付款 | LINE Pay 一鍵收，booking＋販售共用 | **商家憑證**（唯一全域卡點） |
| 3. 穿線 | 下單 → 列印 → 送格 → 穿好 → 通知 → 取件 | **硬體**（GoDex 對位＋RS-485 格口，現場） |
| 4. 販售 | 目錄 → 付款 → 開格 → 扣庫存 → 補貨預警 | 庫存模型✅；付款（同卡點）＋**硬體**（485 開格） |
| 5. 行銷 | 獲客 → lead → LINE 綁定 → 到店 → 回購 | **leads 未合流**（本機 SQLite 孤島） |

> 結論：**「金流憑證」和「硬體」是僅存的實體卡點，其餘都是軟體功夫。**

## 六、會員主線合流（最重要的一步，也是最大洞）

現在同一個客人在三個系統是**三筆不相干的資料**：

```
booking 會員（Email/LINE） ←─┐
smartlocker（取件碼+LINK userId） ←─┼─→ 各自為政，認不出「同一人」
leads.db（FB 名單，本機）  ←─┘
```

**目標**：以 **LINE userId 為全域會員鍵**，leads 匯入 Neon 會員表，行銷成效才量得出來——「這批 FB 來的客人，最後幾個真的訂了場、買了泡麵？」這是無人場館從「自動」升級到「會學習」的關鍵。
