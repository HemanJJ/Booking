# 日常/週/月 維護時程表（工具使用時機）

> 這篇回答「**我每天/每週/每月要用哪些工具、什麼時候用**」。
> 核心：**生意在雲端，程式在 GitHub，資料在 Neon，Mac 只是工具。**
> 掛了先開網站確認，別急；UptimeRobot down 信常是誤報（冷啟動）。
> 紙本接單永遠是最後保險。

---

## 一、每天一大早（先看異常最重要）

**只要 30 秒：雙擊 `🩺 一鍵健康檢查.command`，看紅字。**

| 檢查 | 工具 | 通過= | 異常→ |
|------|------|-------|-------|
| 兩站網站/資料庫 | 健康檢查 ① | 綠 ✅ | 500→Neon；打不開→Vercel |
| LINE 通知額度 | 健康檢查 ② | 剩 >50 則 | 剩少→省著用；用完→等下月重置/升級 |
| OpenRouter 餘額 | 健康檢查 ③ | 剩 ≥$1 | **快沒錢→去 openrouter.ai 儲值** |
| 每週備份有沒有跑 | 健康檢查 ④ | log 今天有更新 | log 舊→開 `💾 備份Neon資料庫.command` 手動跑 |
| git 忘了 push | 健康檢查 ⑤ | 三 repo 同步 | 有 ahead→cd 該 repo && git push |

> **紅字 ❌ = 待辦（附解法）；綠字 ✅ = 放心。** —— 紅字就是你的今日待辦清單。
> 進階：開後台 `/admin` 看四卡（今日訂位/收入/空場/未收款）→ 有數字=活著。

## 二、每週

| 時間 | 自動跑 | 你要做 |
|------|--------|--------|
| 每週日 03:30 | 自動 `pg_dump` → iCloud「Difly備份」（保留 8 份） | 偶爾瞄 `~/tools/logs/neon-backup.log` |
| 每週日 03:35 | `🩺 一鍵健康檢查`（headless）→ 有問題彈 macOS 通知 | 收到通知 → 依紅字處理 |

> **主動要做**：確認 OpenRouter 還有錢（< $1 會自動通知）、看備份 log 有在寫。

## 四、掛了才用的「3 層問法」

```
客人 → Vercel 網站 → Neon 資料庫  (+LINE 平台)
```

| 症狀 | 定位 | 解法 |
|------|------|------|
| 網站打不開 | Vercel | 開 vercelstatus.com；或 `/api/health` 500 |
| 開得開、訂位/下單失敗 | Neon/程式 | `/api/health`:200→程式bug；500→Neon掛 |
| 後台 500 / 找不到欄位 | **Neon 沒套新欄位** | **手動 ALTER**（絕不用 `prisma db push`——共用庫會 drop 穿線的表！） |
| 認證登入問題 | LINE 平台 | 見 [[06-LINE整合]]；**LINE token 別按 Reissue** |
| push 後全站 404 | Root Directory | 設 `web` + `./deploy.sh` 恢復 |
| UptimeRobot down 信 | 冷啟動+北美誤報 | **別理**，自動回 up |
| DB 爆/限流 | Vercel/Neon 免費額度 | 用量爆→升方案 |

## 六、🔴 重大診斷（2026-09-03）：每週自動備份「其實一直沒跑成功」

### 症狀
`🩺 一鍵健康檢查.command` 顯示 `??`（額度/備份/OpenRouter 一堆問號），懷疑有異常。

### 根因（兩層 TCC）
launchd 排程（`com.defi.neon-backup` / `com.defi.weekly-check`）每次執行都報：
```
Operation not permitted
```
- **第 1 層**：腳本放在 **`~/Desktop/projects/code/`**（TCC 保護），launchd（無 GUI 權限）**無法執行**位於 Desktop 的腳本。
- **第 2 層**：即便能執行，腳本**讀 Desktop 下的 `.env`**（`smartlocker/web/.env.local`）也被 TCC 擋。

### 現況證據
- `logs/launchd_neon_backup.log` = **0 bytes**（launchd 從沒成功跑過）。
- iCloud「Difly備份」只有 **8/21** 一份（`neondb-2026-08-21.sql.gz`）→ **之後每週備份都沒新增**。
- `launchd_neon_backup_error.log` 疊滿 `Operation not permitted`。

### 修法（已做 + 需 1 步手動）
**已做**：
1. 把兩個腳本移到**非 TCC 目錄** `~/tools/`（`difly-backup.sh`、`difly-weekly-check.sh`），內部路徑改為指向專案根（讀 Desktop 內容仍允許，只要腳本本身不在 Desktop）。
2. 修 `🩺 一鍵健康檢查.command`：④ 檔名 `launchd_neon_backup.log`→`neon-backup.log`；③ OpenRouter 負數顯示修正。
3. 更新兩個 launchd plist 指向 `~/tools` 腳本 + log 路徑移到 `~/tools/logs/`。

**剩 1 步需要人工（無法用命令授權）**：launchd **讀 Desktop 下的 `.env`** 仍被 TCC 擋（`grep ... .env.local: Operation not permitted`）。
> 解法 = 授「完全磁碟存取權（Full Disk Access）」：
> 系統設定 → 隱私與安全性 → 完全磁碟存取權 → 加入 `/bin/bash`（及 `/usr/bin/python3` 如有用到）→ 重啟該兩個 launchd 任務。

> 替代（較不建議）：把 `DATABASE_URL`/LINE token 等複製到 `~/tools/secrets.env`（非 TCC）讓腳本讀——但**會落地一份生產金鑰，有洩漏風險**。

### 金句
> **Mac 只是工具。備份是命根——備份沒在跑，比網站掛更該先發現。** 用 `🩺 一鍵健康檢查` 的紅字當你的每日待辦。
