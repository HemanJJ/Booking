# UI 踩坑紀錄（2026-08-22 排班板大修）— 老闆實際使用的教訓

> 這篇是「**老闆實際用起來有問題**」的紀錄，不是功能清單。
> 每一條都是使用者真實回報 + 找出根因 + 修法。**新 session 開發 UI 前必讀。**

---

## 一、最重大的坑：Tailwind CSS class 在「部分瀏覽器」不載入

### 症狀（使用者截圖實證）
- modal 彈出後**出現在右下角**（沒置中）
- **沒有黑色半透明遮罩**（背景沒變暗）
- modal **底部按鈕被切掉看不到**（＋30分／完整改單／取消）
- 但**訂位色塊有顏色**（因為那時已改用內聯色）

### 根因
Tailwind v4 產生的 class（`fixed`、`inset-0`、`flex`、`items-center`、
`justify-center`、`bg-black/40`、`overflow-y-auto`…）在**某些瀏覽器（舊版或特定 WebView）
整批沒生效**——CSS 沒載入或瀏覽器不支援 Tailwind v4 的新語法（slash 透明度 `/40` 等）。
結果：樣式全失效，modal 掉到文件流位置（右下角）、無遮罩、按鈕被視窗切掉。

### 修法（已上線，根治）
**關鍵互動元素的樣式改用「內聯 style 屬性」**，不依賴 Tailwind class：
```jsx
// modal 外層：遮罩＋定位＋捲動
style={{
  position: "fixed", inset: 0, zIndex: 50, overflowY: "auto",
  backgroundColor: "rgba(0,0,0,0.45)",
}}
// 內層：置中
style={{ display: "flex", minHeight: "100%", alignItems: "center", justifyContent: "center", padding: 16 }}
// 卡片：白底圓角陰影＋限高可捲
style={{
  margin: "auto", width: "100%", maxWidth: 384, borderRadius: 16,
  backgroundColor: "#fff", padding: 20, boxShadow: "0 20px 50px rgba(0,0,0,0.3)",
  maxHeight: "85vh", overflowY: "auto",
}}
```
- `rgba()` / `position:fixed` / `display:flex` / `min-height` / `overflow-y` 都是**瀏覽器原生支援**，
  與 Tailwind 版本無關。
- **結論**：modal 這類「功能性定位」樣式一律內聯；Tailwind class 只用在「非關鍵美化」。

### 通用原則（以後開發 UI 照做）
1. **功能必需的樣式**（定位、遮罩、置中、捲動、可見性）→ **內聯 style**。
2. **純美化**（顏色、圓角、間距、hover）→ 才用 Tailwind class。
3. 每個 UI 做完，**用「非 Chrome 的瀏覽器」或「縮小視窗」測一遍**：
   - 縮到 700px 寬 × 500px 高（模擬小筆電/老螢幕）
   - modal 要能捲動看到全部按鈕
4. **色塊/狀態色**（pending 琥珀、confirmed 綠）→ 內聯 `backgroundColor`，
   不要用 `bg-amber-500` 這類 Tailwind 色 class（曾出現漏載變成白格）。

## 二、modal「視窗矮就切掉底部」的修法

### 症狀
modal 內容比視窗高時，**底部按鈕被切掉、無法捲動** → 使用者以為「不能 edit」。

### 根因
原本用 `items-center`（垂直置中）＋ 外層無 `overflow-y-auto`，
modal 比視窗高時上下溢出且無法捲動。

### 修法（已上線）
三層結構：
```jsx
<div style={{ position:"fixed", inset:0, overflowY:"auto", backgroundColor:"rgba(0,0,0,0.45)" }} onClick={onClose}>
  <div style={{ display:"flex", minHeight:"100%", alignItems:"center", justifyContent:"center", padding:16 }}>
    <div style={{ margin:"auto", maxWidth:384, maxHeight:"85vh", overflowY:"auto", ... }} onClick={e=>e.stopPropagation()}>
```
- 外層可捲動（整個畫面捲）＋ 卡片自身 `maxHeight:85vh` 也可捲。
- **任何視窗高度，往下捲都能看到全部按鈕。**

## 三、排班板互動的坑（快速點擊 race）

### 症狀
「點一下色塊＝快速編輯」**偶發沒反應**；拖移 ghost 不出現。

### 根因
原寫法：`pointerdown → setState → React re-render → useEffect 才掛 window 監聽`。
**快速點擊**時 `pointerup` 比 React 渲染還快到 → 監聽還沒掛 → 事件丟失。

### 修法（已上線）
監聽改為**在 `pointerdown/mousedown` 當下同步 `attachListeners()`**、`up` 時 detach
（用 ref 存 handler，每次 render 更新）。不再等 React re-render。

### 補充：瀏覽器相容
- 舊瀏覽器（Safari<13、舊 Edge）**不支援 PointerEvent** → 原本整個板子全失效。
- 後來**全面改用 Mouse Events**（`onMouseDown/mousemove/mouseup`，所有瀏覽器都支援），
  並保留「✏️ 編輯按鈕」走 `onClick`（最保險的路徑）。
- **教訓**：互動優先選 Mouse Events + onClick；Pointer Events 只在需要觸控拖移時用。

## 四、no-show 自動判定的通知轟炸（LINE 額度用盡）

### 症狀
- 使用者 LINE 一次收到 11 封「自動判定 no-show」通知 → 氣到叫 AI 刪 demo 資料。
- 之後 LINE 通知全失效：`{"message":"You have reached your monthly limit."}`。

### 根因
`autoMarkNoShows()` 首次執行把 11 筆「已結束＋未標記」的舊訂位**一次全判 no-show 並逐筆發 LINE**。
LINE 官方帳號免費方案**每月僅 200 則**，一次轟炸＋累積用量 → 額度用盡。

### 修法（已上線）
- **自動判定不再逐筆發 LINE**：只寫 `BookingLog`（後台「異動紀錄」可查）。
- 只有「有人累計達 3 次被停權」才發**一封彙整通知**。
- 後台**人工標記**「未到」仍逐筆通知（櫃台主動操作，該通知）。
- 寬限期 `NO_SHOW_GRACE_HOURS` 6h → **24h**（給櫃台整天補標時間，避免打完球沒多久就誤判）。

### 驗證額度是否用完（排障用）
```bash
curl -H "Authorization: Bearer $LINE_MESSAGING_ACCESS_TOKEN" https://api.line.me/v2/bot/message/quota
# → {"type":"limited","value":200}
curl -H "Authorization: Bearer $LINE_MESSAGING_ACCESS_TOKEN" https://api.line.me/v2/bot/message/quota/consumption
# → {"totalUsage":200}  # 200/200 = 用完，等下月重置或升級方案
```

## 五、其他小坑

| 坑 | 根因 | 修法 |
|----|------|------|
| 「保留中」色塊顯示成**白格** | Tailwind `bg-amber-500` 漏載 | 改內聯 `backgroundColor:"#f59e0b"` |
| 「現在時間紅線」太淺看不到 | 原本 2px 淺紅 | 使用者要求**還原原生樣式**（細線＋標籤）→ 尊重原設計，別亂改 |
| 拖移/點擊沒反應 | PointerEvent 舊瀏覽器不支援 | 全改 Mouse Events |

## 六、給新 session 的鐵律

1. **老闆（使用者）測不出來 ≠ 功能壞**：先問「瀏覽器名稱版本」「截圖」，
   再查 `BookingLog`（後台操作都有紀錄）確認他到底做了什麼。
2. **Tailwind class 不可靠**（尤其 v4）：功能性樣式一律內聯。
3. **modal 一定要能捲**：任何視窗大小，底部按鈕都要看得到。
4. **通知要克制**：自動化動作（cron）不逐筆發 LINE；只有人工動作和重大事件才發。
5. 改 UI 後**自己用縮小視窗測**，別只在開發機大螢幕看。
