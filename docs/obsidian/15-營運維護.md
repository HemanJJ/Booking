# 營運與維護（部署 / 角色 / 故障排除）

> 給老闆（vibe coding）的維運速查。改程式後部署、開員工帳號、出問題先看這。

## 一鍵部署（不用再 vercel login）

- 長期 token 存在專案根目錄 **`.vercel-token`**（已 gitignore，勿上傳 GitHub）。
- 部署指令：進專案目錄後打 **`./deploy.sh`**（等同 `vercel --prod --token=…`，免登入）。
- token 到期日設「No Expiration」＝永久有效，除非手動 revoke。
- token 失效時：https://vercel.com/account/tokens → 重建 → 覆寫 `.vercel-token`。
- 改「資料表欄位」不能只部署，還要把新欄位 ALTER 到 Neon（見下）。

## 角色權限（3 層）

| 角色 | 進後台 | 能做的事 |
|------|:---:|------|
| `member` 會員 | ❌ | 前台訂位、看自己訂位 |
| `staff` 員工 | ✅ 櫃台作業 | 儀表板、代客下單/改單/拖移、收款、固定訂位 |
| `admin` 館長 | ✅ 管理後台 | 全部（報表、價位、場館場地、會員、異動紀錄） |

- 開員工：後台 → 會員管理 → 點「**設為員工**」。
- 敏感功能（報表/價位/會員/異動）對員工**雙層鎖**：頁面自動導回 + server action 擋。

## 資料庫（最重要的地雷）

- 本地 SQLite、生產 **Neon 與租拍/穿線「共用同一個庫」**。
- ⚠️ **絕對不要跑 `npx prisma db push`**：它會把租拍/穿線的表 drop 掉。
- 改 schema 的正確做法：
  1. 同步改 `prisma/schema.prisma` 與 `prisma/schema.postgres.prisma`。
  2. 本地：`npx prisma migrate dev --name 名字`。
  3. 生產：用 `Pool` 跑「只 ADD COLUMN / CREATE TABLE 的 ALTER」（別 drop 別人的表）。

## 故障定位 SOP（先判斷斷在哪一層）

系統是一條線：**客人 → Vercel 網站 → Neon 資料庫**（＋ LINE 平台，用到 LINE 才碰得到）。

| 步驟 | 做什麼 | 結果判讀 |
|------|--------|---------|
| ① 網站活嗎 | 開 `https://difly-booking.vercel.app` | 打不開 → Vercel（查 vercelstatus.com） |
| ② DB 活嗎 | 開 `https://difly-booking.vercel.app/api/health` | 回 500 → Neon 掛；回 200 → DB 好 |
| ③ 哪邊壞 | 前台/後台/LINE 哪邊異常 | 見下 |

- **線上壞、本地好** → 部署/環境變數問題（多半忘了 `./deploy.sh` 或漏設 Vercel 環境變數）。
- **本地也壞** → 程式碼 bug → 貼錯誤給 AI。

常用後台：Vercel（vercelstatus.com / Dashboard→Logs）、Neon（console.neon.tech）、LINE（developers.line.biz + manager.line.biz）。

## 故障排除速查

| 症狀 | 原因 | 解法 |
|------|------|------|
| `vercel --prod` 報 Not authorized | 短期 login token 過期 | 改用 `./deploy.sh` |
| 後台 500 / 找不到欄位 | Neon 沒套上新欄位 | 手動 ALTER（見上） |
| LINE 點「預訂場地」跳首頁/錯頁 | LIFF Endpoint 不是 `/liff` | 見 [[06-LINE整合]] |
| 圖文選單換圖/改按鈕 | API 建的選單 console 看不到 | `npx tsx scripts/richmenu.ts list` |
| UptimeRobot 報 down、網站卻打得開 | 冷啟動＋北美節點誤報 | 別理，幾分鐘自動回 up |
