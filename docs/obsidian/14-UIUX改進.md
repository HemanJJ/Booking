# UI/UX 改進清單（PRD）— 老闆視角

> 目標：讓老闆「**打開手機 3 秒知道現況、30 秒完成一件事**」。
> 這是給新 session 的實作需求，依優先序 P0 → P1 → P2。

---

## P0（第一版必做）

### 1. 後台 dashboard 重設計：今日總覽卡

**第一眼就要看到數字，不要品牌 banner。**

四張卡（今日）：

| 卡 | 內容 |
|----|------|
| 今日訂位 | 今天共幾筆（例：12 筆） |
| 今日收入 | 今日已收款＋預估（例：$5,600） |
| 空場數 | 目前幾面場空著（例：3 面場空著） |
| 未收款 | 幾筆訂位「未收款」（例：2 筆未收款） |

下面緊接「**今日時間軸**」（見第 2 點）。

### 2. 「現在此刻」畫面：今日 7 面場時間軸

- 後台一個「**今日**」視圖。
- **7 面場 = 7 列**，橫軸 = 營業時間（08:00–00:00）。
- 每格標色：
  - 🟢 空著（可訂）
  - 🔴 使用中（現在正在打）
  - 🔵 已預訂（未來）
- 每面場左側顯示即時狀態：**「使用中 / 空著 / 下一場 14:00」**。
- 一條**紅線**標示「現在時間」，自動往前跑。
- 日報表**動態更新**（有訂位/取消/開打，即時反映）。

### 3. 老闆代客下單／改單

後台要有「**＋ 代客下單**」按鈕：

- 選客人（搜既有會員，或臨時輸入姓名＋電話）。
- 選場地＋日期＋時段＋時長 → 建立。
- 可**改單**：改時段、改時長、換面場、取消。
- 這是老闆每天最常用的功能（客人現場臨時改）。

### 4. 收款標記（現金已收／未收）

- 訂位加「付款狀態」：`未收`／`已收（現金）`／`LINE Pay（未來）`。
- 後台一鍵切換。
- dashboard「未收款」卡直接反映。

### 5. 預訂保留 24 小時機制（MVP 無金流的繳費機制）

- 訂位建立後 = **「保留中」**（先佔住時段）。
- **24 小時內**必須「繳費」或「扣點數」，否則**自動釋放時段**。
- 繳費方式（MVP）：
  - 臨櫃現金 → 老闆後台標「已繳費」。
  - 點數 → 會員有「點數」就扣點（點數系統為後續功能，先留欄位）。
- 未來接 LINE Pay：付款成功 = 自動「已繳費」。

## P1（第二版）

### 6. 拖移搬訂位（推拉）

- 在「今日/週表」視圖上，**把訂位色塊拖到另一面場的同時段** = 換面場。
- 拖到不同時間 = 改時間。
- 系統自動檢查目標時段是否空（防重疊，沿用現有唯一鍵）。

### 7. 通知分級

- **新訂位** → 安靜（不吵，可每日彙整一封，或不 push）。
- **取消／變更** → 即時響（push，老闆最需要立刻知道）。
- 做法：`sendLineAdminNotify` 加「優先級」參數；新訂位走「低頻/彙整」，取消變更走「即時」。

### 8. 手機優化（桌機為主＋手機常用操作）

- **桌機仍為主**（週表、時間軸用桌機）。
- 手機只做**常用操作**的精簡版：
  - 今日總覽卡（4 張數字）。
  - 今日時間軸（可橫滑）。
  - 代客下單、收款標記。
- 原則：**手機能「查＋一鍵改」，複雜排版留桌機**。

---

## P2（第三版）

### 9. 「查閱場地」icon 互動引導訂閱

- 前台「查閱場地」頁（客人看占用）改為**可點選**：
  - 點一個空時段 = 選它（訂 1 小時）。
  - 再點下一格 = 加 1 小時（累加時長）。
  - 選完 → 引導登入／下單。
- 目的：讓客人「看到空場 → 直接點 → 訂」，降低使用門檻（老人家也會用）。

---

## 非功能性需求

- 全程繁體中文。
- 桌機為主，手機為輔。
- 沿用現有防重疊、價位規則、LINE 通知基礎。
